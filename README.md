# STRELK / Стрелк — Точный выстрел 0.2.0

**Original Android game inspired by the timing-puzzle genre.** This is an independent implementation written in Java and Canvas, with procedural artwork. It contains no assets, code, level files or third-party advertisement placements copied from `com.codef.arrow`.

## What is playable in this repository

- 1200 reproducible challenge configurations, generated by `LevelFactory.java` (not copied from the reference game).
- Animated central target; attaching flying arrows with overlap detection, speed/rotation/direction patterns.
- Progression, earned coins, 4 arrow designs, unlockable cosmetics, fullscreen UI and persistent progress.
- Rewarded ad for an extra attempt after failure, +150 coins from the arsenal, or doubling a level bonus. Rewards **only** on Yandex's `onRewarded()` callback.
- Interstitials at level transitions, after at least 3 victories, every 3rd victory, with a 180-second cooldown. Not shown during play.
- When ad units are not configured: no advertising displayed, ad rewards hidden. Internet is not needed to play.

## Build debug APK

Choose Actions > **Android debug APK** > Run workflow, or let it run on pushes to `main`. Wait for green success, open the build, download artifact `strelk-0.2.0-debug-apk`. Unzip the artifact, then install `app-debug.apk` on Android.

Local Android Studio build: open this folder, sync Gradle, Build > Build APK(s). Requires JDK 17, Android SDK 35, Gradle 8.10.2 (configured by CI). The source ZIP doesn't include a Gradle wrapper; Android Studio can select an installed Gradle version.

Debug APK is *not* a RuStore release! For RuStore, configure a long-lived release keystore, increment versionCode, make a signed release APK/AAB and preserve your signing key. Do not upload a debug-signed build as production.

## Set your own Yandex Advertising Network IDs

Create an app and two ad blocks in the [Yandex Advertising Network](https://partner.yandex.ru/): rewarded and interstitial. Plug them in at build time:

```bash
gradle assembleDebug -PstrelkRewarded=R-M-XXXXXX-1 -PstrelkInterstitial=R-M-XXXXXX-2
```

Replace `XXXXXX` with real numbers from your account. These IDs are examples, not working identifiers. Build-time settings: `BuildConfig.REWARDED_ID` and `BuildConfig.INTERSTITIAL_ID`. There are no IDs from the original game and no Google/AppLovin/Meta ad code in this project. The sole advertising SDK used here is Yandex Mobile Ads v8.6.0. To test placement use Yandex demo IDs in debug builds only (never in release). Yandex ad SDK doesn't run until unit IDs are present.

**Earnings are not guaranteed**: ad availability, region, fill rate, eCPM, and active users determine revenue. Ad exposure in debug without real IDs earns nothing. Add a real privacy policy and declare SDK data processing, advertising identifiers and any analytics in the RuStore disclosures. App-ads.txt and the app ownership verification may also be required by the network.

## Reference-package analysis / limitations

Provided XAPK `Arrow - Now with 1200 levels_5.0.6_APKPure.xapk`: base APK + ARM64 split; package `com.codef.arrow`; app `Arrow` version 5.0.6 (367), min API 29, target API 37 per XAPK metadata; Unity IL2CPP, metadata/data assets and multiple Android DEX archives. Includes Google Mobile Ads, AppLovin/Meta and Firebase-related components. Google Play lists developer PuLu Network, advertisement and IAP support. Public gameplay description confirms tap-to-launch pins into a rotating circle, failure on contact, increasingly complex levels and speed variations.

This is a **static package analysis** plus public screenshots/descriptions, **not** a runtime emulator playthrough or a reverse-engineered source-code reconstruction. Thus precise reference level layouts, menu flow, ad display frequency and its hidden server-side flags are not verified. The 1200 configs in STRELK are generated and have smoke tests, but they have not yet been human playtested/curated or verified as perfectly balanced. Shipping requires physical-device and ad SDK QA.

## Original design

Minimal cream-colored gameplay field, black circular hub, numbered black projectiles on thin shafts, and small vector arrowheads incorporated within those shafts. Upper toolbar includes achievements, store, level selection and settings. These visuals are drawn independently in Java Canvas, rather than transferred from the reference APK. Initial configurations are original procedural levels and are not verified identical to those in the reference game.
